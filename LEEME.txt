POO_Java_TF_Gr2 - Gestión de proyectos

ABRIR Y EJECUTAR
1. En NetBeans: File > Open Project y seleccionar esta carpeta.
2. Seleccionar POO_Java_TF_Gr2 en Projects.
3. Ejecutar con F6. La clase principal es Vista.UsaProyecto.
4. Para editar la ventana: abrir Vista/UsaProyecto.java y elegir Design.
   UsaProyecto.form contiene los controles y sus eventos para el diseñador.
5. Para generar el ejecutable: Run > Clean and Build Project.
   El resultado queda en dist/POO_Java_TF_Gr2.jar.

Requiere un JDK para compilar y un entorno gráfico para Swing.
El código utiliza Java 8; se compiló y probó con el JDK 24 de NetBeans 26.
No requiere Maven, base de datos, bibliotecas descargadas ni conexión a Internet.

USO
- Registrar proyecto: título, fecha ISO, duración y unidad, cliente y gerente.
- El código se genera automáticamente con el año de registro y el mayor
  consecutivo existente para ese año más uno: aaaa-001 a aaaa-999.
- Puede registrar un equipo al crear el proyecto o agregarlo después.
- Un cliente existente se reutiliza por identificación.
- El estado inicial es INICIADO. Use Actualizar estado para cambiarlo.
- Las consultas aparecen en el área central y permiten copiar su contenido.
- Guardar proyectos conserva los proyectos completos, sus clientes y empleados.
- Guardar clientes escribe el cliente de cada proyecto; Leer clientes elimina
  repetidos por identificación y permite reutilizarlos en nuevos registros.
- Leer proyectos reemplaza la lista en memoria, previa confirmación si hay datos.
- Los archivos datosProyectos y datosClientes se guardan en la carpeta de trabajo.
  En NetBeans es normalmente la carpeta del proyecto.
- Los cambios no se guardan automáticamente. La ventana indica cambios pendientes
  y advierte al salir. Guardar clientes no sustituye Guardar proyectos.
- Cancelar un registro o la captura de un equipo no agrega datos parcialmente.
- Los datos de las pruebas son ficticios y se guardan en una carpeta temporal.

ESTRUCTURA Y CORRESPONDENCIA CON EL PDF
Modelo/Proyecto.java: atributos, dos constructores, accesores, fecha final,
  agregar/eliminar integrantes y toString con la información completa.
Modelo/Empleado.java: identificación, nombre, título profesional y experiencia.
Modelo/Cliente.java: clase abstracta con los tres atributos protegidos del UML.
Modelo/Empresa.java: subclase final; contiene su Contacto.
Modelo/PersonaNatural.java: subclase final con teléfono y correo.
Modelo/Contacto.java: nombre, cargo, teléfono y correo.
Vista/UsaProyecto.java: JFrame, listas estáticas y TODOS los métodos del diagrama.
Modelo/Validacion.java y ArchivoObjetos.java: auxiliares para evitar duplicación.
test/Pruebas: comprobaciones automatizadas y caso para depuración paso a paso.
evidencias: resultados reales de ejecución y comprobaciones del trabajo.

DECISIONES ANTE AMBIGÜEDADES DEL ENUNCIADO
- El PDF dice "8 dígitos" pero muestra 2026-001: se interpreta como 8 caracteres,
  incluidos el guion y los tres dígitos del consecutivo.
- El año del código es el de registro, independiente de la fecha de inicio.
- La fecha de finalización es estimada: fechaInicio más la duración indicada,
  mediante LocalDate.plusWeeks/plusMonths/plusYears.
- Leer clientes abre datosClientes; la mención a datosProyectos en esa nota del
  PDF se interpreta como una errata, por el nombre y el contenido del método.
- El UML usa eliminarIntegranteProyectoDadoCodigo y la nota usa retirar:
  se incluyen ambos nombres, con un alias que delega en el mismo comportamiento.
- Agregar equipo conserva los integrantes anteriores. Evita duplicados por ID
  y valida toda la lista antes de modificar el proyecto.
- No se inventan restricciones de longitud para IDs, nombres, teléfono o correo;
  solo se exige contenido. La experiencia debe ser no negativa y caber en byte.
- No se inventan transiciones entre estados: se permiten los seis del PDF.

PRUEBAS
En Files, clic derecho sobre build.xml > Run Target > pruebas.
También puede ejecutar la clase Pruebas.PruebasProyecto con Run File.
Desde una terminal con JAVA_HOME y Ant configurados: ant pruebas
El objetivo pruebas compila, ejecuta y actualiza evidencias/resultado-pruebas.txt.
Las pruebas utilizan verificaciones explícitas, no necesitan activar -ea ni JUnit.
Si algo falla, terminan con error y Ant informa BUILD FAILED.

DEPURAR EN NETBEANS
1. Abrir Modelo/Proyecto.java y ubicar determinarFechaFinalizacion().
2. Colocar un breakpoint en la primera línea ejecutable del método.
3. Abrir Pruebas/DepuracionProyecto.java y elegir Debug File (Ctrl+Shift+F5).
4. Al detenerse, revisar this.fechaInicio, this.unidadDuracion y
   this.duracionEstimada en Variables. Se esperan 2026-01-31, meses y 1.
5. Avanzar con Step Over (F8), continuar con F5 y comprobar 2026-02-28.
